# T-269 evidence — Harden OAuth runtime configuration and Gateway DPoP replay protection

## DDD record before implementation

- Bounded context: Edge authentication plus the Identity issuer composition boundary.
- Use case: resolve OAuth configuration after Nest configuration loading and enforce production-safe Gateway DPoP verification.
- Aggregate: none; this is stateless request verification plus atomic, expiring replay reservations.
- Invariants: Identity and Gateway defaults match; configured issuer wins after `ConfigModule.forRoot`; the effective Gateway request URL uses the canonical public origin; one replay key is accepted at most once across instances; production fails closed without shared replay configuration; bearer authentication remains supported.
- Consistency boundary: one conditional DynamoDB write per DPoP proof key, shared by all Gateway instances.
- Affected ports: Better Auth `DpopReplayStore`; no business-domain port.
