# T-269 — Separate OAuth request orchestration from vendor verification

## DDD implementation record

- Bounded context: shared OAuth resource technical boundary.
- Use case: verify one OAuth credential and map it to owned claims.
- Aggregate: none; credential verification is stateless.
- Invariants: Better Auth remains the cryptographic authority; the adapter
  implements `OAuthCredentialVerifierPort`; `OAuthResourceService` consumes
  `VerifyOAuthCredentialUseCase` and never implements the port; credential
  errors and critical coverage remain unchanged.
- Consistency boundary: one request verification.
- Affected ports: `OAuthCredentialVerifierPort`.

## TDD evidence

direct-construction API remains compatible and routes through the same adapter.
