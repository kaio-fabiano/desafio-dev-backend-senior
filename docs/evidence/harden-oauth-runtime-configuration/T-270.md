# T-270 — Add canonical and replay-safe Gateway DPoP configuration

## DDD implementation record

- Bounded context: Edge authentication.
- Use case: atomically reserve DPoP proof identifiers and verify each proof
  against the canonical public request target.
- Aggregate: none; each record is an expiring security tombstone.
- Invariants: one replay key succeeds once across Gateway instances; expired
  tombstones can be replaced despite DynamoDB TTL deletion delay; DPoP uses the
  public Gateway origin; production fails closed without shared replay storage;
  Bearer credentials remain supported.
- Consistency boundary: one conditional DynamoDB reservation.
- Affected port: Better Auth 1.7.1 `DpopReplayStore`.

### Green

`DynamoDpopReplayStore` now implements Better Auth 1.7.1's reservation contract
with one conditional DynamoDB `PutItem`. The condition accepts a missing or
expired tombstone and rejects a live duplicate atomically; unrelated DynamoDB
errors fail closed. `GatewayAuthModule` supplies that store when configured and
rejects production startup without its table.

SST now creates one TTL-enabled `GatewayDpopReplay` table, links it to Gateway,
sets `DPOP_REPLAY_TABLE`, and sets `GATEWAY_ORIGIN` from `publicApi.url`. The
existing request adapter continues to construct the canonical request URL, and
Better Auth still accepts ordinary Bearer tokens.
