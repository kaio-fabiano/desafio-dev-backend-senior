# T-271 — Enforce Identity query visibility and use the production batch provider

## DDD implementation record

- Bounded context: Identity.
- Use case: list users administratively and find only a self-visible or
  administratively visible user.
- Aggregate: none; Better Auth remains authoritative for user reads.
- Invariants: ordinary scopes cannot enumerate users or email addresses; self
  and `me` remain visible; denied cross-user reads match missing users; batching
  and caching stay request-scoped; PageInfo derives from persisted rows.
- Consistency boundary: one Identity GraphQL request and its Better Auth read
  snapshot.
- Affected port: `IdentityUserQueryPort`.

## TDD evidence

### Red

Commands:

```text
pnpm exec vitest run libs/identity/nest/src/graphql/identity.resolver.spec.ts libs/identity/nest/src/graphql/identity.graphql.integration.spec.ts libs/identity/nest/src/infrastructure/persistence/better-auth-identity-user.adapter.spec.ts libs/identity/nest/src/better-auth/better-auth.factory.spec.ts --reporter=verbose
NODE_ENV=test TSX_TSCONFIG_PATH="$PWD/tsconfig.base.json" node --import tsx --test --test-reporter=tap test/graphql-relay-dataloader-closure.test.mjs test/identity-federation-refactor.test.mjs test/idiomatic-nestjs-architecture.test.mjs
```

Results: FAIL for the expected behavioral reasons. The focused tests showed
that `marketplace:read` could list users, cross-user point reads returned the
stored user, Better Auth did not advertise `identity:users:read`,
`hasPreviousPage` trusted only the presence of `after`, and both legacy aliases
still existed. The production request-scoped provider behavior already passed.

### Green

`IdentityUserVisibilityPolicy` now grants point reads only to a
`marketplace:read` subject reading itself or a token with
`identity:users:read`. The global GraphQL guard still authenticates point and
reference operations, while denied and missing IDs both return `null`; `me`
retains its existing subject and scope behavior. Only `identity:users:read`
may execute `users`.

Better Auth 1.7.1 remains the sole user store and now exposes the administrative
scope only for the Identity resource. Pagination asks the Better Auth adapter
whether any row exists at or before `after`, so a valid but non-matching cursor
does not imply a previous page. Nest resolves the existing
`FindIdentityUsersUseCase` provider per request, and the obsolete `UserLoader`
and `IdentityUserRepository` aliases were removed.
