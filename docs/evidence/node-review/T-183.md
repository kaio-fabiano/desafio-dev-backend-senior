# T-183 — Decorator runtime, test ownership, and coverage evidence

## Red

Before changing the application tooling, the focused contract command was:

```sh
pnpm exec vitest run libs/gateway/nest/src/node-review-tooling.spec.ts
```

It failed for the expected behavior: the reviewed application project files
used `--experimental-transform-types` and `vitest.config.ts` discovered only
library specs. The assertions reported that the project source did not contain
`node --import tsx`, and that Vitest did not include `apps/**/*.spec.ts`.

An initial probe placed outside the configured Vitest glob produced `No test
files found`; it was moved under `libs/gateway/nest/src` before recording the
assertion failure above, so the Red result is not a discovery or fixture error.

## Green

`tsx` can transform the workflow's parameter decorators when
`TSX_TSCONFIG_PATH=tsconfig.base.json` is present. Without that setting,
esbuild rejects parameter decorators because it cannot find
`experimentalDecorators`. TypeScript build commands use the same base config,
which retains both `experimentalDecorators` and `emitDecoratorMetadata`.

The current reviewed gateway and identity decorators are invoked manually and
do not consume constructor design metadata. The workflow runtime does consume
normal Nest decorator syntax; an annotated Vitest test launches it in a `tsx`
subprocess and resolves an explicitly injected provider through a Nest
`TestingModule`. `tsx` does not emit `design:paramtypes`, so the runtime must
use explicit `@Inject` tokens where metadata would otherwise be required.
The TypeScript build setting does not alter `tsx` output.

## Nx cache ownership

After `pnpm exec nx reset`, the first
`pnpm exec nx run @desafio-dev-backend-senior/identity-nest:test` was a cache
miss and the identical second command was a cache hit. A temporary whitespace
edit to `test/identity-federation-refactor.test.mjs` produced a second cache
miss and reran both the identity Vitest spec and the owned TAP test. The edit
was removed after the check. This proves that the explicit workspace-root test
input participates in the identity target hash.

## Follow-up Red and Green

The focused tooling spec was extended before the follow-up configuration edit:

```sh
pnpm exec vitest run libs/gateway/nest/src/node-review-tooling.spec.ts
```

It failed because `onpspec.config.json` did not include application or library
Vitest specs and scanned only a nonexistent root `src/**`. It also failed
because the identity target ran and hashed only
`identity-federation-refactor.test.mjs`. The Green configuration adds the
application/library test and source globs, six identity-owned root tests, and
the package, lockfile, TypeScript, and Vitest configuration inputs that affect
the target command.

After the change, the identity target executed 29 TAP tests from all six owned
root test files. A temporary whitespace edit to
`structural-identity-review.test.mjs` caused an Nx cache miss and reran that
complete target; the edit was removed afterward.
