# T-184 gateway authentication, federation, and loader evidence

## Scope and decisions

Task `T-184` implements `AC-226`. Investigation found 25 source markers
(`NR-001` through `NR-006` and `NR-166` through `NR-184`) plus the 20 findings
in `docs/reviews/gateway-auth-refactor.md`.

The catalog loaders had no production consumer. Their only consumer was the
synthetic P95 and batching probe in `test/milestone-7-load.test.mjs`, so the
logic moved to `test/fixtures/catalog-loaders.ts` and the complete `AC-073`
probe remains intact. `createGatewayAuthMiddleware` also had no runtime caller;
the `AC-064`/`AC-065` harness now exercises the Nest-owned context factory.

The gateway GraphQL endpoint remains private. Authentication completes during
context creation, while subgraphs keep operation scope and ownership checks.

Primary-source review established these implementation constraints:

- NestJS providers use decorators and constructor injection. Explicit
  class-token `@Inject()` annotations remain because the repository's tsx
  runtime does not emit `design:paramtypes`.
- Better Auth verification remains in `OAuthResourceService`, which enforces
  ES256, signature, issuer, audience, expiration, issued-at, subject, optional
  not-before, scope normalization, JWKS caching, and rotation.
- Apollo Gateway 2.14.4 uses `make-fetch-happen`/`minipass-fetch`; its
  `Headers.raw()['set-cookie']` API preserves repeated cookies. Native
  `getSetCookie()` and scalar `get()` are compatible fallbacks.
- The request cookie allowlist contains only documented WooCommerce cart state:
  `woocommerce_cart_hash`, `woocommerce_items_in_cart`, and the
  `wp_woocommerce_session_` prefix.

## Red

Before production edits, focused behavioral specs reported **7 failed and 2
passed**. Each failure reached the intended assertion: flat context shape,
untrusted request URL, unfiltered cookies, a masked JWKS outage, implicit bearer
forwarding, subject-coupled correlation, ignored session capabilities, or
collapsed response cookies.
