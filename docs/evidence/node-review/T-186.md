# T-186 — Identity application and GraphQL consolidation

## Red

`vitest run libs/identity/nest/src/graphql/identity.resolver.spec.ts` initially
failed because a malformed Relay cursor reached the user path and raised a
TypeError instead of a GraphQL input error.

## Green

The maintained Nest library now owns GraphQL resolver metadata, user reads,
Relay cursor validation, request-scoped batching, and the public application
API. The application imports only that library. Obsolete app-local Better Auth,
PostgreSQL user repository, GraphQL schema, registration, and supplier runtime
paths were removed after their test consumers were moved to supported library
or test-fixture boundaries. Better Auth remains the sole identity store.

## Marker dispositions

NR-007–NR-019 and NR-021–NR-041: removed obsolete app-local duplicate runtime
paths; health and app composition use standard Nest decorators. NR-020: the
supported bootstrap remains in `apps/identity-subgraph/src/main.ts`; it creates
the Nest application with the deliberate raw-body setting required by the auth
handler, resolves `IdentityAuthBootstrap`, enables shutdown hooks, and reads
the configured port. The historical review marker was removed without changing
that behavior. NR-221–NR-226: replaced manual decorators with native Nest
decorators, isolated Better Auth reads in one provider, retained request
cache/batching, and restricted the package entry point to `IdentityModule` and
`IdentityAuthBootstrap`.
