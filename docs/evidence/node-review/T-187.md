## Finding dispositions

| Findings | Disposition and evidence |
| --- | --- |
| NR-042, NR-043, NR-046, NR-047 | Keep the application service, repository port, and adapter port boundaries. They isolate domain behavior from Nest and MikroORM while concrete providers remain replaceable. The conditional PostgreSQL `INSERT ... ON CONFLICT ... WHERE` atomically grants an expiring lease; a read-then-write ORM sequence would reintroduce a race. |
| NR-044, NR-063, NR-071, NR-085 | Use one exported `PaymentMethod` string union in the checkout port. A TypeScript enum would add runtime code without improving this two-value wire contract. New confirmations require a method; the entity remains nullable for rows created by earlier migrations. |
| NR-045 | Keep explicit `EntityManager.transactional` callbacks because checkout and outbox must share the exact transaction object. Add `clear: true` to claims and confirmations so concurrent operations use isolated identity maps. |
| NR-048, NR-072, NR-073 | Keep constructor injection and the existing Nest custom-provider factories. Decorators are unnecessary on classes instantiated by `useFactory`, and explicit tokens remain reliable when `tsx` does not emit `design:paramtypes`. Provider wiring remains owned by T-189. |
| NR-049, NR-056 | Validate in the application service because callers include GraphQL and reconciliation paths; a transport pipe would cover only one entry point. Runtime validation now rejects non-string required values, unsupported methods, and invalid Card fields before repository or Woo calls. |
| NR-050 | Preserve command-hash conflict detection and database lease claiming. PostgreSQL concurrency tests prove one owner per operation key and rejection of conflicting commands remains covered. |
| NR-051, NR-054 | Preserve explicit reconciliation by stable Woo metadata. Unknown remote outcomes retain `CREATING_WOO`; the next lease owner performs a lookup and never issues a second create. Missing remote state raises the typed pending error. |
| NR-052, NR-055 | Keep the cohesive orchestration in one service. Extracting one-use classes or files would obscure the lease/create/reconcile/confirm sequence without changing behavior. |
| NR-053 | Do not hold a database transaction across WooCommerce network I/O. Local confirmation locks the owned operation and commits workflow plus outbox in one transaction; real PostgreSQL rollback tests prove atomicity. |
| NR-057, NR-058, NR-060, NR-076, NR-077, NR-080, NR-081, NR-082 | Keep small boundary parsers. The adapter now validates cart lines, ISO-style currency codes, positive totals, safe-integer range, and exact BRL fraction precision before mutation. Decimal text is converted with `BigInt`, avoiding binary floating-point rounding. |
| NR-059, NR-061, NR-065 | Keep stable machine-readable codes on typed errors and human-readable message literals at their throw sites. Enums for one-use messages would add indirection without a protocol benefit. |
| NR-062, NR-064, NR-066, NR-067, NR-068 | Keep the standard-library SHA-256 helper and deterministic canonicalizer. JSON key ordering must be normalized before hashing. Characterization vectors prove existing command hashes and Woo references are unchanged. |
| NR-069, NR-070, NR-074, NR-075, NR-079, NR-084 | Keep Woo transport response shapes private to the adapter and export only port types. The endpoint and service credentials are injected once by the Nest provider; buyer session headers remain per request. Literal header, GraphQL field, REST route, and metadata names are protocol values. |
| NR-078 | Keep remote `findByReference` followed by create. MikroORM upsert APIs apply only to the local PostgreSQL store; WooCommerce is an HTTP system. The durable database lease and stable remote reference provide cross-process idempotency. |
| NR-083 | Keep the existing `Map` that coalesces same-process requests. Cross-process exclusion is supplied by the database lease; tests cover both layers. |
| NR-151 | Keep `CheckoutOperationStatus` beside the persisted entity because MikroORM needs runtime values for `@Enum`; the application imports that same definition rather than duplicating status literals. |
| NR-152, NR-154, NR-157 | Decorator diagnostics were resolved by T-183's TypeScript decorator configuration. App build and runtime entity metadata tests pass; no entity rewrite is needed. |
| NR-153, NR-155, NR-156, NR-158 | Keep indexes in migrations, which are the deployed schema authority. Existing unique indexes cover operation keys, Woo references, checkout/workflow links and Woo order IDs; partial indexes cover expired checkout recovery and unsent outbox scans. Inbox lookup uses its primary key. |
| NR-159 | Keep the current `defineConfig` and manually composed request-scoped entity manager. Official MikroORM Nest integration is optional; adding a package solely to replace valid explicit providers is unnecessary. T-189 owns any later module wiring change. |
| NR-160 | Keep one ordered migration stream for the order-workflow database. Host, port, database, user, password, and TLS are environment-specific, so different deployment networks do not change migration ordering or target ownership. The PostgreSQL integration suite applies every migration from an empty database. |

## Sources checked

- [MikroORM transactions and concurrency](https://mikro-orm.io/docs/transactions): explicit transaction callbacks, automatic flush, and isolated transaction contexts.
- [MikroORM EntityManager API](https://mikro-orm.io/api/6.6/core/class/EntityManager): `transactional(..., { clear: true })` isolation guidance for concurrent handlers.
- [MikroORM indexes and unique constraints](https://mikro-orm.io/docs/indexes): entity metadata and database indexes serve different schema/query needs; this project deploys the reviewed indexes through migrations.
- [MikroORM with NestJS](https://mikro-orm.io/docs/usage-with-nestjs): request-specific entity-manager state is required; the project supplies an explicit request-scoped fork.
- [TypeScript enums](https://www.typescriptlang.org/docs/handbook/enums.html) and [everyday union types](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html): a string union is sufficient for the type-only payment-method contract and avoids unnecessary runtime enum output.
