# T-188 evidence — inbox, outbox, messaging, and saga

## Scope and references

- Acceptance criterion: `AC-230` — duplicate events apply once, retryable
  failures remain recoverable, acknowledgements follow durable work, and
  shutdown releases messaging resources.
- Runtime references reviewed:
  - [NestJS RabbitMQ transport and manual acknowledgements](https://docs.nestjs.com/microservices/rabbitmq)
  - [amqplib channel, mandatory return, consumer, and confirm APIs](https://amqp-node.github.io/amqplib/channel_api.html)
  - [RabbitMQ acknowledgements and publisher confirms](https://www.rabbitmq.com/docs/confirms)
  - [RabbitMQ reliability guide](https://www.rabbitmq.com/docs/reliability)
  - [MikroORM 6.6 `EntityManager#getTransactionContext`](https://mikro-orm.io/api/6.6/core/class/EntityManager)
  - the pinned `@mikro-orm/core@6.6.16` `Connection.execute(query, params, method, ctx)` declaration in `node_modules/@mikro-orm/core/connections/Connection.d.ts`

Direct `amqplib` remains appropriate here. Nest's RMQ transport supports manual
acknowledgement, but this runtime also needs mandatory-return detection,
publisher confirms on two independent publishing channels, delayed retry
topology, and explicit ownership of reconnect and shutdown. Replacing the
runtime with the Nest transport would not remove those requirements.

## Red, Green, Refactor

The following focused Red failures were captured before their corresponding
production edits:

- `pnpm exec vitest run apps/order-workflow-subgraph/src/messaging/rabbitmq.spec.ts --reporter=verbose`: 3 failures showed that an acquired connection was not closed after channel creation failed, retry attempt `-2` routed to undeclared retry `-1`, and a delivery without message metadata threw before bounded retry routing.
- `pnpm exec vitest run apps/order-workflow-subgraph/src/messaging/rabbitmq.spec.ts -t 'contains transport' --reporter=verbose`: emitting an amqplib connection error threw an uncaught `Error: socket lost`.
- `pnpm exec vitest run apps/order-workflow-subgraph/src/saga/order-event.consumer.integration.spec.ts --reporter=verbose`: a saga validation failure left one real PostgreSQL inbox row committed instead of rolling the claim back.
- `pnpm exec vitest run apps/order-workflow-subgraph/src/checkout/checkout.repository.integration.spec.ts -t 'rolls back a claim' --reporter=verbose`: a forced failure after claim insertion left one real PostgreSQL checkout operation committed.
- `pnpm exec vitest run apps/order-workflow-subgraph/src/messaging/rabbitmq.spec.ts -t 'caps an oversized' --reporter=verbose`: an oversized retry header was republished as `9007199254740992` rather than the bounded terminal attempt `4`.

Green fixes:

- Every transaction-bound raw checkout, inbox, saga, stock-item, outbox-command,
  and `pg_notify` statement now passes the callback entity manager's transaction
  context to the pinned low-level connection API. The atomic PostgreSQL SQL is
  retained, while rollback now covers the entire durable operation.
- RabbitMQ initialization closes a connection acquired before setup failure,
  installs required EventEmitter error listeners, closes channel before
  connection, and makes runtime close idempotent.
- Retry metadata is normalized and capped. Missing identifiers receive a stable
  content/routing-key digest so poison deliveries enter the bounded retry/DLQ
  path instead of immediate requeue loops.
- The outbox checkout event uses the shared `PaymentMethod` union.

Refactor preserved the existing protocol names, publisher confirms, mandatory
publishing, consumer acknowledgements, retry/DLQ topology, operation keys,
transactional outbox, inbox idempotency, `SKIP LOCKED` claims, atomic attempt
increments, and transactional PostgreSQL notifications.

## Marker dispositions

- **NR-122:** Resolved by review. The persisted disposition enum and its small repository port remain colocated with their only adapter; splitting them adds navigation without a separate reuse boundary.
- **NR-123, NR-127:** Fixed. Raw statements now receive MikroORM's active transaction context; real PostgreSQL proves rollback and eight-way duplicate claiming.
- **NR-124:** Retained intentionally. Parameterized `INSERT ... ON CONFLICT ... RETURNING` is the atomic PostgreSQL inbox claim and avoids a check-then-insert race.
- **NR-125, NR-126:** Retained as a parameterized, transaction-bound completion update; it records workflow, disposition, and database-clock completion together.
- **NR-133, NR-136:** Resolved by runtime and primary-doc review. Direct amqplib is required for the service's confirm, mandatory-return, retry topology, and channel-isolation contract. Focused and real-broker tests cover it.
- **NR-134:** Retained. The exported, versioned queue name is a shared topology contract used by tests and deployment composition; it is not a secret or environment-specific SST resource value.
- **NR-135:** Retained. An `as const` routing-key tuple provides literal-union inference and iteration without a runtime enum object.
- **NR-137:** Retained and verified. The lifecycle implements Nest application bootstrap/shutdown hooks and owns availability, reconnect serialization, timer cancellation, idempotent close, and ORM shutdown.
- **NR-138:** Retained as one parameterized JSON-column projection and fixed by binding it to the saga transaction. Loading a full managed aggregate would add identity-map work without improving this read.
- **NR-139:** Retained after security/performance review. Resource-leak, uncaught-error, malformed-metadata, confirm, retry, and unroutable-message regressions were added.
- **NR-140:** Resolved by review. Publication ports and the small orchestration class remain cohesive in one file.
- **NR-141:** Retained. The runtime deliberately constructs the publisher with a dedicated long-lived entity-manager fork and confirm channel. Nest provider rewiring belongs to T-189 and is unnecessary for this boundary.
- **NR-142:** Retained. `50` is a safe bounded default and the method parameter already permits an explicit operational/test override. Environment configuration would require validation without changing behavior.
- **NR-143:** Retained intentionally. The transaction holds each `SKIP LOCKED` claim through broker confirmation and conditional `markSent`; failed/unknown outcomes remain unsent for at-least-once retry.
- **NR-144:** Retained as an internal invariant error containing the durable event ID. No caller branches on an error category, so a custom class or enum adds no behavior.
- **NR-145:** Retained as the `'v1'` TypeScript discriminant required by the event contract. Protocol versions must not vary by environment or mutable database state.
- **NR-146, NR-147:** Resolved by review and integration coverage. The port/adapter stay cohesive, while real PostgreSQL verifies enqueue, conditional updates, and concurrent claims.
- **NR-148:** Retained as the compile-time event discriminant for checkout's single command. A runtime enum would duplicate the wire value.
- **NR-149:** Retained intentionally. `publication_attempts + 1` must execute atomically in PostgreSQL. Eight concurrent real-database increments finish at eight.
- **NR-150:** Retained intentionally. Conditional `nativeUpdate` performs single-statement attempt/sent transitions without loading stale managed entities.
- **NR-161, NR-162:** Resolved by domain and transport review. The deterministic saga state machine remains independent of Nest transport concerns. Tests cover every event path, out-of-order retry, terminal replay, compensation command, and validation boundary.

All 26 assigned markers were removed from `src/inbox`, `src/outbox`,
`src/messaging`, and `src/saga`; no marker was renamed or hidden.

## Behavioral evidence

- Real PostgreSQL 17 proves transaction rollback after inbox/checkout inserts,
  exactly one inbox winner under eight concurrent deliveries, saga + inbox +
  command atomicity, `SKIP LOCKED` disjoint claims, conditional sent updates,
  and lossless concurrent attempt increments.
- Real RabbitMQ 4.1 proves a persistent confirm, manual delivery processing,
  first-delay redelivery, and rejection of a confirmed mandatory unroutable
  publish.
- Unit tests prove setup cleanup, error-event containment, retry/DLQ routing,
  malformed metadata handling, publisher nack/throw behavior, acknowledgement
  ordering, lifecycle reconnect/shutdown, outbox marking, and saga transitions.
