# T-189 evidence — workflow GraphQL, bootstrap, and SSE

## Scope and references

- Acceptance criterion: `AC-231` — GraphQL mutations and subscriptions enforce
  ownership and scopes, preserve the published schema and graphql-sse protocol,
  and release replay and subscription resources on disconnect and shutdown.
- Runtime references reviewed:
  - [Nest middleware](https://docs.nestjs.com/middleware)
  - [Nest lifecycle events](https://docs.nestjs.com/fundamentals/lifecycle-events)
  - [Nest GraphQL subscriptions](https://docs.nestjs.com/graphql/subscriptions)
  - [graphql-sse Express adapter](https://the-guild.dev/graphql/sse/docs/modules/use_express)
  - [MikroORM usage with NestJS](https://mikro-orm.io/docs/usage-with-nestjs)
  - the pinned Nest 11.1.6 GraphQL shutdown implementation and graphql-sse
    2.6.1 Express adapter in `node_modules`

Nest middleware owns `/graphql/stream` before the application begins listening.
The route continues to use graphql-sse's distinct-connection protocol and the
Apollo-built schema; Nest's `@Sse()` decorator is for ordinary observable SSE
controllers and does not implement the GraphQL over SSE wire contract.

## Red, Green, Refactor

Focused Red was captured before production edits:

- `pnpm exec vitest run apps/order-workflow-subgraph/src/subscriptions/sse.integration.spec.ts --reporter=verbose` failed with HTTP 406 from Apollo's `/graphql` handler because the deferred Express route was registered after Nest's terminal routing handlers and was unreachable.
- The first shutdown Green attempt streamed an event but timed out in `app.close()`. The pinned `GraphQLModule` stopped Apollo before `BeforeApplicationShutdown`, so the Apollo HTTP drain waited for the active SSE response before the subscription registry could abort it.
- `pnpm exec vitest run apps/order-workflow-subgraph/src/health.controller.spec.ts --reporter=verbose` failed because readiness still called the deprecated raw `select 1` path instead of `MikroORM.checkConnection()`.

Green registers middleware through `NestModule.configure`, enables
`stopOnApplicationShutdown`, passes an abort signal through graphql-sse context,
and waits for accepted streams to finish after abort. A stopping gate returns
503 before new handler work starts. Client disconnect resolves tracked lifetime
even when the pinned Express adapter's final `response.end(callback)` cannot
complete after a destroyed socket. Credential failures return a stable 401;
unexpected verification failures remain 500 responses without exposing their
message.

Refactor moved GraphQL transport types and the operations token out of the
resolver, replaced callback/generic resolver indirection with an injected
operations port, reused the shared `PaymentMethod` and persistence status enum,
and reuses one replay provider for live relay and subscriptions. The public
schema, route, OAuth scopes, subject-bound lookups, replay version ordering, and
session forwarding are unchanged.

## Marker dispositions

  `unknown` data argument is the canonical callback contract, and the returned
  session type now aliases the checkout port's shared session type.
- **NR-089, NR-093–NR-095:** Retained with explicit composition. The operations
  service is the GraphQL application adapter and remains request-scoped because
  its checkout service and entity manager are request-scoped. Constructor
  dependencies use explicit `@Inject` tokens, which also works in test runners
  that do not emit `design:paramtypes`.
- **NR-090–NR-092, NR-098:** Fixed. GraphQL-facing types moved to
  `order-workflow.types.ts`, and payment methods reuse the checkout port's
  `PaymentMethod` union.
- **NR-096:** Fixed. Persistence states are compared with
  `CheckoutOperationStatus` and mapped to the unchanged GraphQL status contract.
- **NR-097:** Retained. The small pure `orderView` function keeps transport
  mapping separate from persistence calls without adding a provider.

  factory are composition concerns and remain next to the module that consumes

- **NR-102:** Fixed. The Nest module now owns the SSE middleware, shutdown

- **NR-103–NR-108, NR-114–NR-115, NR-118:** Fixed. Resolver types and tokens moved

- **NR-109–NR-111, NR-113:** Resolved by review. Resolvers delegate directly so
  Nest/Apollo's guard and exception layers retain consistent GraphQL error

- **NR-112:** Fixed. The non-decorated subscription helper was removed from the
  mutation/query resolver.
- **NR-116–NR-117:** Retained as two focused resolver classes in one cohesive
  GraphQL adapter file: one handles the `Order`/query/mutation fields and one
  handles the independently scoped subscription provider.
- **NR-119:** Resolved. Stable `Symbol` provider tokens remain the Nest-supported
  interface injection mechanism and the operations token moved beside the
  other workflow tokens.
- **NR-120:** Fixed and verified by decorator-enabled typecheck plus actual Nest
  application startup.
- **NR-121:** Fixed. Readiness uses `MikroORM.checkConnection()` and rejects an
  explicit `{ ok: false }` result.
- **NR-128–NR-129:** Fixed. Bootstrap now delegates initialization and listening
  to Nest, runs migrations through the current `orm.migrator` API, and has no
  custom body-parser or post-initialization route phase.

  the HTTP routing stack is finalized. AC-201 now records this resolved behavior

- **NR-131:** Retained consistently with NR-100; the existing provider owns the
  ORM lifecycle and is shared by bootstrap and messaging.
- **NR-132:** Fixed. Bootstrap uses the supported `orm.migrator.up()` API.
- **NR-163:** Retained as a dedicated read adapter and registered once as a Nest
  provider. Its parameterized join is a narrow durable-replay projection; every
  call uses a fresh entity-manager fork and does not run inside a caller-owned
  transaction, so no transaction context is omitted.
- **NR-164–NR-165:** Fixed. The existing graphql-sse package remains the wire
  implementation and is hosted through Nest middleware with schema, OAuth,
  disconnect, and shutdown integration.

All 44 assigned markers were removed from the reviewed workflow GraphQL,

## Behavioral evidence

- A real HTTP client opens `/graphql/stream`, receives an owner-bound event in
  graphql-sse framing, and observes no other owner's broker channel.
- Missing and invalid credentials receive 401, missing scopes are forbidden,
  and an unexpected verifier outage remains a non-leaking 500.
- Mutation integration proves scope enforcement and forwarding of the verified
  subject, payment method, and WooCommerce session headers.
- Unit tests prove replay/live ordering, duplicate suppression, terminal
  completion, overflow failure, replay/broker failure, heartbeat/idle closure,
  abort cleanup, shutdown admission gating, resolver delegation, status mapping,
  parameterized replay, and health readiness.
