# T-217 implementation record

- Bounded context: Identity.
- Use cases: register an external customer identity, compensate a failed
  registration, and provision the two first-party OAuth clients.
- Aggregate: none. Better Auth and the external customer system own separate
  authoritative state, so no local transactional aggregate exists. Each use
  case invocation is the consistency boundary; registration uses compensation
  when the cross-system link cannot be completed.
- Invariants: bootstrap registration never provisions a customer; incomplete
  sign-up results do nothing; only a customer created by the current attempt is
  deleted; all independent cleanup steps run; client provisioning is idempotent,
  links every delegated resource, requests seed credentials only for a missing
  client, and never publishes partial client identifiers.
- Affected ports: `CustomerIdentityPort`, `IdentityAccountPort`,
  `OAuthClientProvisioningPort`, and `OAuthSeedCredentialsPort`.
- Compatibility: public GraphQL, OAuth, Better Auth hook, environment, and
  persistence behavior remains unchanged.
- Red evidence: `pnpm exec vitest run
libs/identity/nest/src/identity-core.architecture.spec.ts --reporter=tap`
  failed because the framework-independent classes did not exist and the two
  NestJS services did not delegate to the required use cases.
